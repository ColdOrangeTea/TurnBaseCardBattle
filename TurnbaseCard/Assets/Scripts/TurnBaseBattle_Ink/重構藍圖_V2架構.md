# 回合制卡牌戰鬥 — V2 重構藍圖

> 目的：把目前「能跑但很亂」的戰鬥系統，重寫成**單一 Prefab、直接引用、單一資料來源**的乾淨架構。
> 策略：**保留已驗證的運算核心，重寫編排／接線／資料歸屬三層**，並以**平行 V2** 方式進行——
> 舊系統原封不動還能跑，V2 在 Editor 驗證通過後再切換、刪舊。

## 一、現況為什麼亂（四個病根）

| # | 病根 | 具體症狀 | 位置 |
|---|------|----------|------|
| 1 | 大腦與畫面分成兩個 Prefab | 無法在 Inspector 互相拖引用，只能執行期用 `Tag` + `GetChild(index)` 硬接 | `BattleManagerRoot` vs `BattleEmpty` |
| 2 | `GetChild(index)` 接線 | 全專案 40+ 處；調換任一子物件順序就默默壞掉 | `TurnBaseBattleUI`、`TurnBaseBattleManager.Init*`、子系統 |
| 3 | 兩條靜態事件匯流排當隱形全域變數 | 資料在 Manager↔Unit↔Action 之間乒乓來回，追不到真正持有者 | `BattleTurnBaseEvent`、`DiceEvent` |
| 4 | 同一份數值存三份 | `DisplayData` / `Manager.temp_*` / `BattleAction.temp_*` 靠事件不斷同步 | 三處 |

**核心結論**：病根 #1（兩個 Prefab）逼出了 #2、#3、#4。合併成單一 Prefab + 直接引用 + 單一資料來源，四個病根一起消。

## 二、V2 目標架構

### 單一 Prefab `Battle`
```
Battle (根，掛 BattleController)
├─ View                     ← 純顯示，被 Controller 用 [SerializeField] 直接指定
│   ├─ Background
│   ├─ PlayerPanel (P1)      HP條 / 名字 / 骰數 / 狀態圖示
│   ├─ EnemyPanel  (P2)
│   ├─ CardArea              4 卡槽
│   ├─ DiceArea (P1 / P2)
│   ├─ TurnLabel             回合數 / 輪到誰
│   ├─ Buttons               下一回合 /（作弊）
│   └─ Settlement            勝 / 敗
├─ Systems                  ← 直接拖引用，不再 GetChild
│   ├─ DiceSystem
│   ├─ DrawCardSystem
│   └─ NumericalCalculation
└─ Units
    ├─ PlayerUnit  (BattleUnit)   ← 單一真實資料來源
    └─ EnemyUnit   (BattleUnit)
```

### 三個新核心類別
- **`BattleUnit`**：單一真實資料來源。存 HP / 骰數 / 狀態 / 順位，狀態一變就發 `Changed` 事件給 View 刷新。取代 `DisplayData` 的資料角色與 `temp_*` 的三份副本。
- **`BattleView`**：純顯示。`[SerializeField]` 指定所有 UI 物件；只提供 `Refresh(context)`，不訂閱任何事件、不含遊戲邏輯。取代 `TurnBaseBattleUI` 的 450 行 `GetChild` 快取。
- **`BattleController`**：唯一大腦。`[SerializeField]` 直接持有 View / Systems / 兩個 BattleUnit / BattleAction。內含回合狀態機、敵人 AI、勝負判定。**直接讀寫 BattleUnit，不再走事件乒乓**。取代 `TurnBaseBattleManager` 的 730 行。

### 保留不動（已驗證的運算核心）
`CardCalculation`、`StatusValueSetter`、`BattleStatusEffect` / `BattleCardInfo` / `BattleEffectInfo`、
SO 資料（`SO_BattleUnitStats`、`SO_BattleStatusEffectData`）、骰子/抽牌的數學與物件池、VFX/Spine 顯示。

## 五、關鍵設計原則（貫穿全部）
1. **禁用 `GetChild(index)` 與 `FindWithTag` 接線**——一律 `[SerializeField]` 在 Inspector 拖。
2. **一份資料**——runtime 狀態只存在 `BattleUnit`；View 只讀不存、Controller 直接讀寫。
3. **顯示與邏輯分離**——View 不含任何遊戲規則；Controller 不直接動 UI 物件，只呼叫 `view.Refresh()`。
4. **事件只用於「對外通知」**，不用於「內部傳資料」。
